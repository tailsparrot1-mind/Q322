# Vkus Kali Selenium — community search fix

Изменения:
- поиск сообществ использует реальный маршрут VK: `https://vk.ru/search/communities?q=...`;
- старый `search?c[q]=...&c[section]=communities` удалён из основного маршрута;
- Vkus больше не пытается вручную переключать вкладку «Сообщества» после открытия общего поиска;
- ожидание результатов сообщества увеличено, а при отсутствии выдачи в ошибке показывается фактический адрес, который открыл Firefox;

## Вкладка «Биржа» (UI)

Добавлена отдельная вкладка «Биржа» в боковую навигацию. В интерфейсе есть переключение между заявками, специалистами и собственными публикациями; фильтры по запросу, региону, городу и направлению; выбор источников VK, Telegram, Avito, YouDo, Профи.ру и форумов.

Важно: в этой версии реализован интерфейс. Коннекторы внешних площадок, сбор реальных публикаций, классификация намерений и создание публикаций ещё не подключены. Вкладка явно показывает это состояние и не выдаёт демонстрационные записи за реальные результаты.

## Личный архив результатов VK — пользовательская модель

- Vkus продолжает использовать текущую авторизацию в отдельном Firefox-профиле: участник самостоятельно входит в собственный VK в открытом браузере. Пароль VK не запрашивается и не передаётся Vkus.
- При первом поиске приложение спрашивает согласие на долговременное сохранение результатов. При отказе поиск продолжается, но расширенный архив не создаётся. В разделе «Первичная настройка» есть кнопка «ЛИЧНЫЙ АРХИВ», чтобы включить или приостановить сохранение позже; отключение не удаляет уже сохранённую БД.
- При согласии результаты поисков записываются в SQLite: ~/.vkus/demand.sqlite3. Там же хранится история поисковых запусков и связи найденных записей с запросами.
- База локальная для текущего системного пользователя и установки Vkus. Она не отправляется в Supabase и не объединяется с базами других участников. На POSIX-системах права каталога/файла ограничиваются до 0700/0600 (best effort).
- Повторные находки дедуплицируются по типу, URL и нормализованному тексту; повторное обнаружение обновляет время последнего обнаружения.
- В текущей версии используется один активный VK-сеанс на один локальный профиль Vkus. Отдельный VK ID OAuth-токен не реализован: OAuth-вход VK ID сам по себе не предоставляет права на браузерный поиск публикаций.
- Автоматический сбор через VK API и общая облачная база VK-данных не включены. Для такого сценария отдельно требуется проверить условия VK и получить необходимые разрешения.
- Запись выполняется в поисковом worker-потоке, не блокируя Tk UI. На POSIX-системах каталог и файл БД получают права 0700/0600 (best effort).
- Текущая строка результата показывает число записей, добавленных/обновлённых в локальной базе. Полноценный экран просмотра, фильтрации и удаления архива — следующий этап, не заявляется как готовый.


## Личный архив спроса — визуальная полировка

- Архив использует отдельную тёмную тему Vkus: сине-фиолетовая рабочая поверхность, контрастные голубые заголовки, согласованные состояния вкладок и прокрутки.
- Таблица получила увеличенную высоту строк, улучшенную типографику и различимое оформление постов и комментариев.
- Панель подробностей больше не выглядит пустым чёрным блоком: до выбора записи показывает понятную подсказку, после выбора — полную карточку публикации.
- Фильтры, история поиска, открытие ссылок, удаление записей и локальная SQLite-модель не меняются.
- Проверка визуала выполняется тем же UI smoke-тестом smoke_demand_archive.py; снимок окна сохраняется как артефакт. Smoke-тест использует тестовые записи и не подтверждает живой VK-сбор.
