## Решение пользователя

Пользователь согласовал поэтапный запуск магазина на бесплатной инфраструктуре Cloudflare как стартового проекта. ## Правила использования workers.dev

Официальная документация рекомендует production Workers на Workers Route или Custom Domain. workers.dev предназначен для личных/хобби-проектов, не являющихся business-critical. Документация не формулирует запрет как «любая оплата автоматически запрещена», поэтому нельзя утверждать, что тестовые или ранние продажи запрещены; одновременно нельзя обещать, что платёжный магазин гарантированно соответствует правилам платформы. Перед запуском реальных продаж следует повторно проверить действующие условия Cloudflare и при необходимости получить письменное подтверждение поддержки.
Источник: https://developers.cloudflare.com/workers/configuration/routing/workers-dev/

## Совместимость с Vkus и Robokassa

- Настольное приложение Vkus — Python/Tkinter, WebView интегрирован через `vkus/license_store.py`.
- Worker будет отдельным HTTPS API на TypeScript/JavaScript; Vkus обращается к нему через HTTPS. Переписывать Python-приложение не требуется.
- Cloudflare Workers Static Assets может обслуживать storefront; Worker — API и callbacks; D1 — заказы, лицензии и статусы.
- Robokassa официально документирует iFrame и допускает использование в WebView при технической совместимости. Это не гарантия совместимости с конкретной версией WebKitGTK/tkwry; требуется отдельный smoke/integration test в нашем окне.
- Robokassa требует серверной проверки подписи ResultURL и ответа `OK{InvId}`. SuccessURL — только пользовательский возврат, не доказательство оплаты.
Источники:
- https://docs.robokassa.ru/ru/iframe.html
- https://docs.robokassa.ru/ru/notifications-and-redirects.html
- https://docs.robokassa.ru/ru/quick-start

## Требования безопасности (обязательные для реализации)

1. Пароли Robokassa №1 и №2 хранятся только в Cloudflare Worker Secrets. Не хранить их в Q322, браузерном коде, клиенте Vkus, конфигурации `vars`, логах или отчётах.
2. Цена/название/тариф берутся из серверного каталога тарифов, а не из параметров клиента.
3. Создание заказа и платёжной подписи выполняется на сервере.
4. ResultURL проверяет подпись выбранным в кабинете Robokassa алгоритмом, сумму, номер заказа, валюту/идентификатор магазина и ожидаемый статус. Значения алгоритма и параметры должны соответствовать реальному кабинету.
5. Обработка callback идемпотентная: уникальный InvId, уникальная запись события/платежа, повторный callback не создаёт вторую лицензию.
6. SuccessURL/FailURL не изменяют статус платежа. UI показывает «ожидает подтверждения» до серверного подтверждения.
7. Ключи лицензий генерируются криптографически стойким генератором. В базе хранить хэш ключа/идентификатор, а не открытый ключ без необходимости; выдача открытого ключа должна быть защищена и ограничена.
8. Vkus активирует лицензию только после серверной проверки ключа и статуса; локальная проверка в клиенте не является источником истины.
9. Rate limiting, проверка размеров/типов входных данных, CORS allowlist, защита от повторов, безопасные HTTP-заголовки и минимизация персональных данных.
10. Логи не должны содержать платёжные пароли, полные ключи, персональные данные и полные callback payloads.
11. Должны быть документированы резервное копирование/экспорт D1 и процедура восстановления. Time Travel на Free — 7 дней, это не полноценная независимая резервная копия.
12. При достижении лимитов D1 API должен возвращать контролируемую ошибку и сохранять возможность повторной обработки callback; нельзя подтверждать оплату до успешной фиксации статуса в БД.

Cloudflare Secrets: https://developers.cloudflare.com/workers/configuration/secrets/
D1 security: https://developers.cloudflare.com/d1/reference/data-security/
Rate limiting: https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/

## Ограничения и неизвестные параметры

- У пользователя пока нет подтверждённого аккаунта Cloudflare; регистрация, создание Worker/D1 и выдача публичного адреса не выполнены.
- Нет подтверждённых MerchantLogin, пароля №1, пароля №2 и выбранного алгоритма подписи Robokassa. Не запрашивать секреты в чате; добавлять их в Cloudflare Secrets после создания Worker.
- Нет подтверждённого почтового провайдера и SMTP/API credentials для доставки лицензии. Нельзя обещать email-доставку до выбора и проверки провайдера.
- Не подтверждена возможность корректной работы Robokassa iFrame внутри используемой версии WebKitGTK/tkwry. Требуется реальный тест.
- В текущем Q322 `vkus/license_store.py` указывает на Lovable URL. Миграция витрины ещё не сделана; существующий Lovable URL не считать допустимой целевой зависимостью.
- Исходники прежней витрины были ранее просмотрены из Lovable, но Lovable не используется для дальнейшей разработки/хостинга. До точного восстановления исходной композиции нельзя объявлять перенос дизайна завершённым.

## Целевая архитектура

```
Vkus 3.28 (Python/Tkinter + WebView)
        |
        | HTTPS
        v
Cloudflare Workers (workers.dev на старте)
  - storefront static assets
  - create order / create payment
  - Robokassa ResultURL
  - SuccessURL / FailURL
  - license activation / validation API
        |
        +---- D1: plans, orders, payment_events, licenses, activations
        |
        +---- Worker Secrets: Robokassa passwords, signing keys
        |
        +---- email provider (отдельно выбрать и проверить)
```

Слой API должен быть независим от клиента Vkus, чтобы позднее перенести его на платный сервер без переписывания desktop-приложения. Внешние интерфейсы и тарифы сохраняются; не менять цены и продуктовую логику без отдельного согласования.
