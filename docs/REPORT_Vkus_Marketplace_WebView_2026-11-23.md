# Vkus Marketplace — переход на HTML/CSS WebView

Дата: 23.11.2026

## Цель
Устранить Tkinter-вид основной доски объявлений. Ориентир — присланный пользователем тёмно-синий Marketplace: стеклянная центральная панель, яркий голубой контур, неоновые кольца на фоне, центральный поиск, яркие действия и карточная сетка.

## Реализация в исходниках
- Основной экран `open_cloud_marketplace_window()` теперь передаёт отображение в `vkus/marketplace_web.py`.
- Используется уже установленный в Vkus `tkwry.WebView` (тот же движок, который открыт для License Store). Новый браузерный движок и отдельный процесс не добавлялись.
- HTML/CSS/JS лежат локально в `vkus/assets/marketplace_web/`; локальный `app=` не требует localhost-сервера и не зависит от загрузки CSS/JS из сети.
- CSS отвечает за стеклянную панель, фоновые световые кольца, градиенты, карточки, фильтры, модальные окна и адаптивную сетку.
- JS отвечает за отрисовку карточек, поиск, категории, модальные формы, профиль и отклики.
- Python RPC через `window.tkwry.invoke()` связывает HTML-интерфейс с существующим `SupabaseMarketplaceClient`.

## Сохранённые операции
- Вход и регистрация с ролью «Соискатель» / «Рекламодатель».
- Гостевой просмотр.
- Публичная выдача и фильтры по запросу, типу, категории и городу.
- Создание и редактирование объявлений.
- Удаление собственных объявлений; проверка владельца остаётся на стороне данных/клиента и Supabase RLS.
- Отклики, входящие отклики и смена статуса отклика.
- Профиль пользователя.
- Внешняя «Биржа» и её код не менялись.

## Ограничения реализации
- Схема `marketplace_listings` пока не содержит подтверждённого поля фото объявления. В карточках используются стилизованные иллюстративные зоны по категориям, а не вымышленные фотографии. Для настоящих фотографий нужен отдельный этап: согласованное поле `image_url`, Supabase Storage, правила загрузки/доступа и превью.
- Сортировка в интерфейсе сейчас соответствует существующему серверному порядку `created_at.desc`; переключатель показывает текущий режим «Сначала новые», дополнительных режимов пока нет.
- В HTML-слое используются стандартные системные шрифты с fallback, чтобы интерфейс не зависел от Google Fonts и интернета.
- Веб-движок `tkwry` находится в Alpha; Linux требует WebKitGTK 4.1, GTK 3, X11/XWayland и сборку Python-модуля с Rust. На Windows требуется WebView2 Runtime.

## Повторный технический аудит перед запуском CI

- Подтверждено по официальной документации tkwry 0.1.9: `@web.rpc("name")` и `window.tkwry.invoke(name, data)` являются корректной парой; WebView `app=` обслуживает локальные HTML/CSS/JS без localhost. Источник: https://github.com/mashu3/tkwry/blob/main/docs/rpc.md.
- Подтверждено, что Linux-установка tkwry не имеет PyPI wheel и собирается из sdist; нужны Rust toolchain, WebKitGTK 4.1 и GTK 3. Эти зависимости присутствуют в `install.sh` и добавлены в Marketplace CI. Источники: https://pypi.org/project/tkwry/0.1.9/ и https://github.com/mashu3/tkwry.
- Повторно проверены `vkus/marketplace_web.py`, `index.html`, `styles.css`, `app.js`, `.github/scripts/smoke_marketplace.py`, `requirements.txt`, `install.sh` и `vkus/app.py`: точка входа приложения сохраняет host frame, а host содержит `_marketplace_webview`; RPC-обработчики используют API, задокументированный tkwry.
- CI smoke использует подменный `SupabaseMarketplaceClient`; он проверяет интерфейс и RPC-связку, но не проверяет настоящие Supabase credentials, RLS, Storage или публикацию в общей базе.
- Официальная документация tkwry помечает 0.1.9 как Alpha; Linux обозначен как best-effort source install. Поэтому целевая проверка Kali/VMware обязательна даже при зелёном GitHub Actions.

На этом commit запускается новый workflow через push в `main`; результат и скриншоты должны быть проверены отдельно. Не считать проверку успешной до просмотра статуса Actions и артефактов.
