# Vkus — личное рабочее пространство VK

## Принятая модель

Один локальный профиль Vkus использует собственный Firefox-профиль участника (~/.vkus/firefox_profile). Участник самостоятельно входит в VK в браузере. Vkus не запрашивает пароль VK и не переносит cookies в облако.

После первого запуска поиска приложение запрашивает отдельное согласие на долговременное архивирование истории результатов (последний экранный результат и раньше сохранялся в настройках). При согласии результаты сохраняются в SQLite ~/.vkus/demand.sqlite3. При отказе поиск продолжает работать, но отдельный архив не пополняется.

## Состав локальной базы

- workspace_meta — идентификатор локального рабочего пространства;
- search_runs — запрос, регион, город, режим и время поиска;
- demand_items — нормализованные поля найденных публикаций/комментариев;
- search_run_items — связь между поисковыми запусками и найденными записями.

Дедупликация выполняется в пределах локального рабочего пространства по SHA-256 от типа материала, URL и нормализованного текста. Повторное обнаружение обновляет last_seen_at; история поисковых запусков сохраняется отдельно.

## Границы данных

- База локальная: данные не отправляются в Supabase и не доступны другим участникам.
- Идентификатор workspace_id обозначает локальное рабочее пространство, а не подтверждённый VK user ID.
- Один профиль Vkus сейчас поддерживает один активный Firefox-сеанс VK. Для нескольких VK-аккаунтов на одном компьютере потребуется отдельный этап с изолированными браузерными профилями и переключением рабочего пространства.
- В текущей реализации используется существующий вход через Firefox, а не OAuth-токен VK ID. OAuth VK ID предназначен для авторизации приложения/пользователя, но сам по себе не даёт произвольного доступа к поиску публикаций через интерфейс VK.
- Не включены VK API ingestion и централизованное объединение персональных данных между участниками.
- Существующий браузерный поиск остаётся отдельным механизмом; эта работа меняет только согласованный локальный архив результатов и не доказывает соответствие автоматизации всем действующим правилам VK.

## Проверки

Unit tests проверяют запись, дедупликацию и изоляцию отдельных рабочих пространств. Они не проверяют вход в VK, Selenium DOM, фактический поиск, работу на Kali/VMware или юридическую допустимость конкретного сценария.
